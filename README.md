# Match Pulse 比分雷达

一个面向个人使用的足球比分监控网页。选择比赛并设置开始时间、轮询频次和比分条件；条件达成后播放提醒音乐并发送桌面通知。

## 已实现

- 按日期加载 API-Football 赛程，支持今天、明天、后天快捷选择和任意未来日期
- 球队名称自动显示为中文，标准中文译名优先，并在本地缓存翻译结果；支持中英文球队名搜索
- 多场比赛选择与任务管理
- 比赛查询与监控管理分为独立页面，查询页专注选比赛，管理页集中查看任务和规则
- 默认每 3 分钟监控，支持 1 分钟及自定义频次
- 立即开始或指定时间启动
- 每个任务可添加多个监控指标，并将指标应用到全部已选比赛或其中一场；每个“指标 × 比赛”只提醒一次，命中后继续监控其他指标
- 支持开赛后持续判断、半场后、每场完场和全部完场四种时机，以及主队领先、主队落后、总进球和比分差指标
- 支持比赛进入半场后判断主客队比分；左侧为主队、右侧为客队，并兼容轮询错过短暂中场状态后在下半场继续判断
- 每轮按监控日期获取一次赛程，再在服务端筛选已选比赛，兼容免费套餐
- 任务持久化、自动停止、错误退避与 SSE 实时提醒
- 默认使用《刘欢 - 好汉歌》，支持试听和上传其他音乐
- 上传歌曲保存在浏览器 IndexedDB，下次打开自动恢复上一次选择
- 启动监控时自动解锁声音权限，并支持桌面通知
- 桌面端与移动端响应式界面

## 运行

要求 Node.js 20 或更高版本。

```bash
npm install
cp .env.example .env
# 在 .env 中填写 API_FOOTBALL_KEY
npm run dev
```

开发页面为 `http://localhost:5173`，服务端为 `http://localhost:8787`。

不填写 API Key 时可以直接使用演示比赛验证完整流程；演示任务在首次检查时会生成完场比分，以便测试提醒。

## 生产运行

```bash
npm run build
npm start
```

访问 `http://localhost:8787`。

## 注意事项

- API Key 仅由 Node 服务读取，不会发送到前端页面。
- 页面右上角可导入多个 API Key，并通过名称和末四位掩码随时切换当前 Key。现有 Key 可通过“编辑”修改名称和绑定平台，也可直接删除；删除当前 Key 后会自动启用剩余 Key，没有剩余 Key 时进入演示模式。环境变量 Key 需从服务器配置中删除。平台修改后旧测试结果会清除，需重新点击“测试”。所有导入值保存在本机 `data/settings.json`（已被 Git 忽略），重启后仍然生效。相同 Key 再次导入会更新名称而不会重复保存；切换后不会自动查询，需点击“查询比赛”验证。
- 每个 API Key 按北京时间独立记录每日真实上游请求次数，并区分比赛查询和连接测试；监控管理页展示所有 Key 最近 7 天的逐日历史，数据通过 SSE 实时更新，缓存命中不会计为上游请求。服务器保留最近 31 天统计。
- 每个 Key 提供手动“测试”按钮。测试会调用一次对应平台并消耗一次请求；成功显示绿色状态和可用的额度信息，失败显示红色状态及分类后的错误信息。测试结果保存在本机，当前 Key 异常时顶部 API 按钮也会变红。
- API 设置支持按 Key 选择数据平台，目前包含 API-Football、TheStatsAPI 与 TheSportsDB。TheStatsAPI 使用 Bearer Key；TheSportsDB 使用 V1 Key（免费测试 Key 可填写 `123`）。各平台的按日足球比赛都会转换为统一的赛程、状态和比分结构。已有任务会记录创建时的平台和 Key，切换平台不会拿另一平台的比赛 ID 查询旧任务。
- 选择日期、打开页面或切换日期不会请求赛事。只有点击“查询比赛”才会读取赛事数据，并优先命中服务端缓存。
- 页面会保存上一次查询日期和精简赛事快照；刷新后立即恢复上次结果，并通过服务端只读缓存接口补全。切换到曾查询过的日期也会读取服务端持久缓存，整个恢复过程不会请求上游比分 API。
- 球队中文名会合并项目维护词库、扩展覆盖表、名称归一化、Wikidata、机器翻译和可选腾讯翻译；只缓存确实包含中文的结果，避免英文回退值长期阻止后续翻译改进。查询页显示中文覆盖数量，每场比赛可分别修正主客队译名，人工修正保存在服务器并在后续比赛中复用。鼠标悬停可查看 API 返回的原名。
- 服务端必须持续运行，定时任务才能按时启动。
- 浏览器需保持打开；点击“启用声音”或“启动监控”会解锁声音权限。
- 不要通过注册多个免费账号绕过 API-Football 配额限制。

## 比分请求失败与恢复

- 请求（含响应正文）最多等待 15 秒，错误会区分 DNS、连接超时、TLS、认证、限流及无效数据。
- 如服务器访问比分接口需要代理，在 `.env` 配置 `HTTPS_PROXY=http://127.0.0.1:7890`（替换为实际地址），重启 Node 服务。支持 `HTTP_PROXY` 和 `NO_PROXY`。浏览器能够访问外网不代表 Node 使用了相同代理。
- 失败后自动以 3、6、12、24、30 分钟退避；不会短于任务原定间隔或服务端 Retry-After。成功后恢复原频次，也可点击“立即重试”。
- 同一日期的页面刷新与所有监控任务共享服务端缓存；并发查询只发送一个上游请求。切换 API Key 不会删除其他 Key 和日期的既有缓存。默认进行中比分缓存 5 分钟，临近开赛 10 分钟，赛前较久 30–60 分钟，完场 6 小时。
- API 返回的每日剩余额度会显示在赛事标题旁。剩余额度达到 10 次保留值后，页面刷新只读取缓存，保留请求供监控任务使用。可通过 `API_FOOTBALL_LIVE_CACHE_SECONDS` 与 `API_FOOTBALL_QUOTA_RESERVE` 调整。
- 更新失败时显示历史比分和最后成功更新时间，不使用旧比分重新判断提醒条件。旧任务首次成功更新前显示“暂无成功更新记录”。
- API Key 或权限错误需修正配置；代理配置不能解决订阅或额度问题。错误信息不回显上游原始内容或密钥。
- Windows 可直接运行 `npm start`；建议 Node.js 20.19 或更高版本。
